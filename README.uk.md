# novaposhta-mcp

[MCP](https://modelcontextprotocol.io)-сервер для API [Нової пошти](https://novaposhta.ua), який лише читає дані. Із ним ШІ-асистент, наприклад Claude, відстежує посилки, шукає відділення й поштомати, населені пункти та вулиці, а також оцінює вартість і строк доставки.

English: [README.md](README.md)

> **Неофіційний проєкт.** Він не пов’язаний із Новою поштою і не схвалений цією компанією. «Нова пошта» — торговельна марка її власника. Ви користуєтеся сервером на власний ризик.

> **Стан: версія 0.1.0.** Кожен інструмент перевірено на живому API без ключа 08.10.2026: `npm run live-check` запускає зібраний сервер і викликає кожен інструмент з усіма його аргументами. Сервер з особистим API-ключем ще не перевірено, а відстеження перевірено лише на номері, якого Нова пошта не знає, тож стисле подання справжньої посилки складено за назвами полів живої відповіді, а не випробувано на власних відправленнях. Докладніше — у розділі [Обмеження](#обмеження).

## Для чого він

- **«Де моя посилка?»** Бот підтримки або голосовий агент відповідає за номером накладної.
- **«Яке відділення найближче і чи працює воно в неділю?»** Асистент знаходить відділення й поштомати в місті з адресами та графіком.
- **«Скільки коштує доставка до Львова і коли вона приїде?»** Оцінка просто з калькулятора перевізника — для консультанта магазину або форми замовлення.

Сервер не створює, не змінює і не скасовує накладні. Інструментів запису в ньому немає, а його клієнт API відхиляє будь-який метод поза коротким переліком довідкових і розрахункових.

## Швидкий старт

Потрібен Node.js 20 або новіший. **Для запуску ключ не потрібен.** Особистий API-ключ із бізнес-кабінету Нової пошти необов’язковий; див. [Налаштування](#налаштування).

> **В npm пакета ще немає.** Доки перший реліз не опубліковано, команди `npx -y @myradostudio/novaposhta-mcp` нижче не працюватимуть. Запускайте сервер із вихідного коду: `git clone https://github.com/myradostudio/novaposhta-mcp`, далі `npm install` і `npm run build` у цій теці, а в налаштуваннях нижче вкажіть `"command": "node"` і `"args": ["/абсолютний/шлях/до/novaposhta-mcp/dist/index.js"]`.

### Claude Desktop

Додайте сервер до `claude_desktop_config.json` (Settings → Developer → Edit Config):

```json
{
  "mcpServers": {
    "novaposhta": {
      "command": "npx",
      "args": ["-y", "@myradostudio/novaposhta-mcp"]
    }
  }
}
```

Якщо маєте ключ, додайте до цього блоку `"env": { "NOVAPOSHTA_API_KEY": "ваш API-ключ" }`.

Якщо у Windows сервер не запускається, вкажіть `"command": "cmd"` і `"args": ["/c", "npx", "-y", "@myradostudio/novaposhta-mcp"]`.

### Claude Code

```bash
claude mcp add --transport stdio novaposhta -- npx -y @myradostudio/novaposhta-mcp
```

### Cursor

Додайте такий самий блок до `~/.cursor/mcp.json` (для всіх проєктів) або `.cursor/mcp.json` (для одного проєкту):

```json
{
  "mcpServers": {
    "novaposhta": {
      "command": "npx",
      "args": ["-y", "@myradostudio/novaposhta-mcp"]
    }
  }
}
```

Будь-який інший MCP-клієнт, що вміє запускати локальний stdio-сервер, налаштовується так само: запустіть `npx -y @myradostudio/novaposhta-mcp`.

Після цього можна запитати, наприклад:

- «Відстеж посилку 20450000000000».
- «Які відділення Нової пошти є в Броварах на вулиці Київській і як вони працюють?»
- «Знайди поштомати в Ірпені».
- «Скільки коштує відправити посилку 2,5 кг із Києва до Львова, з відділення у відділення, з післяплатою 1500 грн? Коли вона приїде, якщо відправити в понеділок?»

## Налаштування

Сервер налаштовується лише змінними середовища, і обидві необов’язкові.

| Змінна | Обов’язкова | Типове значення | Призначення |
| --- | --- | --- | --- |
| `NOVAPOSHTA_API_KEY` | ні | | Особистий API-ключ із бізнес-кабінету Нової пошти. Якщо його задано, він надсилається з кожним запитом. |
| `NOVAPOSHTA_API_URL` | ні | `https://api.novaposhta.ua` | Адреса API. Лише `https://` (звичайний `http://` дозволено тільки для localhost). |

**Про роботу без ключа.** API Нової пошти розраховане на особистий ключ. 08.10.2026 усі сім методів, які викликає цей сервер, відповідали без нього — саме так сервер і перевірено. Нова пошта цього не обіцяє, тому для всього, на що ви покладаєтеся, задайте ключ. Чи змінює ключ відповіді (наприклад, чи враховує тоді оцінка вартості ваш договір), у цьому проєкті не перевіряли.

## Інструменти

Місця позначаються ідентифікаторами GUID, які Нова пошта називає `Ref`. Населений пункт із `search_settlements` має їх два: `Ref` позначає сам населений пункт, а `DeliveryCity` — місто, за яким рахуються тарифи. Інструменти вказують, який саме їм потрібен. Назви населених пунктів і вулиць шукаються українськими літерами; латинку API відхиляє. Суми — у гривнях, вага — у кілограмах.

| Інструмент | Що повертає | Метод API |
| --- | --- | --- |
| `track_parcels` | Статус, маршрут, дати, вагу й вартість до 100 посилок за номером накладної | `TrackingDocument.getStatusDocuments` |
| `search_settlements` | Населені пункти за початком назви: область, кількість відділень і обидва ідентифікатори | `Address.searchSettlements` |
| `search_warehouses` | Відділення й поштомати міста чи населеного пункту: адресу, графік, обмеження ваги, координати | `AddressGeneral.getWarehouses` |
| `list_warehouse_types` | Типи точок обслуговування (поштове відділення, вантажне, поштомат) — для фільтра в `search_warehouses` | `AddressGeneral.getWarehouseTypes` |
| `search_streets` | Вулиці населеного пункту за словом із назви | `Address.searchSettlementStreets` |
| `estimate_delivery_cost` | Вартість доставки між двома містами для заданої ваги; за бажанням — з оголошеною вартістю, об’ємом і післяплатою | `InternetDocument.getDocumentPrice` |
| `estimate_delivery_date` | Орієнтовну дату прибуття між двома містами | `InternetDocument.getDocumentDeliveryDate` |

Кожен метод викликається як `POST https://api.novaposhta.ua/v2.0/json/`.

Примітки до інструментів:

- **`track_parcels`.** Без номера телефону відповідь така сама, як у публічному відстеженні. З телефоном відправника або одержувача Нова пошта додає імена, телефони й адреси; це персональні дані, і вони потрапляють до ШІ-моделі. Номер, якого Нова пошта не знає, повертається з `found: false`. Порожні й нульові поля пропускаються; `all_fields: true` повертає всі поля, що мають значення.
- **`search_warehouses`** потребує місця: `city_name` (повна назва, а не її початок), `city_ref`, `settlement_ref` або `warehouse_ref` для одного відділення. Без місця API повернув би всі відділення країни, тому інструмент відмовляє.
- **`estimate_delivery_cost` і `estimate_delivery_date`** — це розрахунки. Вони нічого не створюють і не резервують. Іноді Нова пошта коригує вхідні дані (наприклад, тип вантажу) і повідомляє про це в `warnings`; інструмент передає ці зауваги далі.

## Модель безпеки

- **Тільки читання, і перемикача для цього немає.** Інструментів запису немає. API має одну адресу й не має HTTP-методу, який відрізняв би читання від запису, тому гарантія — це перелік: клієнт викликає сім названих методів і відхиляє будь-який інший. Окремий тест перевіряє, що кожен інструмент лишається в його межах.
- **Не надсилається нічого, чого не випробувано насправді.** Нова пошта не публікує машиночитного опису свого API. Замість нього в тестах зберігається перелік властивостей, які надсилала жива перевірка і які API прийняв; якщо інструмент надсилає щось інше, тест падає.
- **Чесні анотації.** Кожен інструмент має `readOnlyHint: true`.
- **Сувора перевірка вхідних даних.** Кожен інструмент відхиляє аргументи, яких не знає. Ідентифікатор має бути схожий на `Ref`, дата — на дату.
- **Ключ зберігається лише у вас.** Якщо його задано, сервер читає його зі змінної середовища, надсилає лише на `NOVAPOSHTA_API_URL` і ніколи не виводить у stdout, stderr чи результати інструментів. За перенаправленнями сервер не переходить.
- **Моделі — менше даних.** Запис відстеження має понад сотню полів, відділення — близько шістдесяти; інструменти повертають стислий добір. Російські дублікати назв пропускаються.
- **Жодної телеметрії; дані бізнесу не потрапляють у журнали.** У stderr потрапляють лише повідомлення під час запуску та тип помилки транспорту.

Двох речей сервер за вас не зробить. По-перше, усе, що повертає інструмент, потрапляє до ШІ-моделі, якою ви користуєтеся, і до її постачальника; з номером телефону відстеження повертає персональні дані. По-друге, опис посилки пише її відправник, і модель отримує його без змін, тож у ньому можуть бути чужі інструкції (prompt injection).

## Обмеження

- **Сервер з особистим API-ключем ще не перевірено.** Усе перевірено без нього.
- **Відстеження справжньої посилки до перевірки не входило.** Жива перевірка відстежує вигаданий номер і отримує «не знайдено». Стисле подання знайденої посилки використовує назви полів живої відповіді, але які поля найважливіші в кожному статусі — це судження, а не результат випробування на власних відправленнях. Якщо чогось бракує, скористайтеся `all_fields: true`.
- **Коди статусів не тлумачаться.** Інструмент повертає `StatusCode` і текст статусу від Нової пошти. Єдиний код, на який покладається сервер, — `3`, «не знайдено»; його підтверджено на живому API.
- **Жива перевірка приймала лише номери накладних із 14 цифр**; інші формати, якщо вони є в Нової пошти, передаються до API як є.
- **Документацію для розробників переглянути не вдалося.** `developers.novaposhta.ua` закритий перевіркою від ботів, яку автоматичний клієнт обходити не має. Назви параметрів і поведінку взято з відповідей живого API. Тому ліміти частоти запитів цьому проєкту невідомі, і сервер не розподіляє свої запити в часі.
- **Жодних операцій запису:** створення, зміна й видалення накладних, реєстрів, контрагентів та адрес, виклик кур’єра, повернення й переадресування до сервера не входять.
- **Чого немає:** вашого власного списку накладних, міжнародної доставки, пакування, часових інтервалів, мапи відділень.
- **Формати дат у відстеженні — такі, як в API**, і різняться від поля до поля (`01-10-2026 19:18:12`, `2026-10-02 08:02:03`, `04.10.2026 08:10:48`). Сервер передає їх без змін.
- **Час очікування відповіді фіксований** — 30 секунд на запит.

## Розробка

```bash
npm install
npm run lint          # tsc --noEmit для src/ і tests/
npm test              # збирає dist/ і тести, потім запускає їх через node:test
npm run live-check    # викликає кожен інструмент на справжньому API (потрібна мережа)
```

- `src/methods.ts` — перелік методів API, які сервер може викликати.
- `tests/support/contract.ts` перелічує для кожного методу властивості, які надсилала жива перевірка. Кожен тест інструмента викликає його через справжній MCP-клієнт і передає кожен записаний запит до `assertMatchesContract`.
- `scripts/live-check.mjs` — друга половина: він запускає `dist/index.js` через stdio і викликає кожен інструмент на `api.novaposhta.ua`. Скрипт читає публічні довідники, просить розрахунки й відстежує один вигаданий номер. Запускайте його після зміни того, що надсилає інструмент, а потім оновлюйте перелік.
- `tests/e2e.test.ts` запускає зібраний сервер окремим процесом через stdio; замість API працює локальна HTTP-заглушка.
- Перевірити сервер уручну: `npx @modelcontextprotocol/inspector node dist/index.js`.

Сервер використовує офіційний TypeScript SDK ([`@modelcontextprotocol/server`](https://www.npmjs.com/package/@modelcontextprotocol/server)) і `zod`; інших залежностей для роботи він не має.

Будемо раді повідомленням про помилки та пул-реквестам. Про вразливості пишіть так, як описано в [SECURITY.md](SECURITY.md).
